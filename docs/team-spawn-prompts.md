No tsconfig, next.config, app/, components/, content/ or public/ yet.

Decision (user, 2026-09-18): run the team from WSL Ubuntu inside tmux (`claude --teammate-mode tmux`). WSL state checked the same day: tmux 3.6 present; NO Linux `node`; `which claude` resolved to `/mnt/c/nvm4w/nodejs/claude` (the Windows shim, which cannot drive tmux); no `~/.local/bin/claude`. Both must be fixed by the user before launch. Before spawning, the new lead must confirm `which claude` and `which node` print Linux paths (not under /mnt/c).

node_modules caveat: the partial `node_modules` was installed from Windows, so any native binaries in it (@swc, sharp) are win32 builds. It must be deleted before design-dev runs `npm install` under Linux (`rm -rf` is denied to agents; the user deletes it). Consequence: the final dev server and all builds run inside WSL (reachable from Windows at http://localhost:3000). `out/` itself is platform-neutral.

Lead duties after spawning: review and approve each teammate's plan by message (plan approval is message-based, see the brief's rules), do not implement anything yourself, do the live browser pass if qa-agent cannot, start the final dev server (`npm run dev`) once qa/report.md is all PASS, then shut teammates down by name.
