# blueguitar.art static prototype: project brief

Written by the main session (team lead). This is the source of truth for every teammate. Read all of it before planning. Do not edit this file; if something in it is wrong or ambiguous, message the main session.

## GOAL

Build a static prototype of blueguitar.art for stakeholder review. Robert Dempster is a solo artist who writes, produces, mixes and masters everything himself under his own label, Dolphin Bay Records. This run produces a fully static site that can be uploaded to Cloudflare Pages as plain files and viewed on preview.blueguitar.art. Its only job is to show look, feel and structure so Robert can react to the design before any platform work begins.

## SCOPE (deliberately narrow)

IN SCOPE: design system, page layouts, catalogue browsing, 30 second preview playback, a persistent audio player, and a static export.

OUT OF SCOPE, do not build any of it: no CMS, no database, no authentication, no Stripe or payments of any kind, no API routes, no server actions, no admin panel, no email sending, no cloud storage integration, no analytics, no deployment.

If you find yourself reaching for a backend, you have misread the task. Content lives in typed local files. The site must build with `output: 'export'` and produce a folder of static files that works with no server at all.

## BUSINESS CONTEXT (so the pages say the right things)

- Catalogue is 10 finished tracks. Robert writes, produces, mixes and masters his own work under his own label, and owns composition and master on the tracks he made alone.
- Ownership wording is legally sensitive and unconfirmed for one track, so do NOT write any blanket claim such as "100 percent ownership of the entire catalogue" anywhere on the site. The licensing page states that he is the sole writer, producer and rights holder on his own recordings, and that per-track ownership details are confirmed on enquiry. Track 10 is a collaboration and must not carry any sole-ownership claim at all. Flag this wording in docs/build-notes.md as needing the client's sign-off before the site goes public.
- Two audiences. Fans who will eventually buy downloads. Music supervisors who license music for film and adverts, decide in seconds, and need ownership stated plainly plus filtering by mood and tempo.
- Tracks appear under The Blue Guitar, Robert Dempster, and one collaboration credited to The Blue Guitar and DUBi.
- He is based in Bloomfield Hills, Michigan, north of Detroit. The label is Dolphin Bay Records.

## STACK (exactly this; nothing added without messaging the main session first)

- Next.js App Router, current stable, TypeScript strict, with `output: 'export'` in next.config and `images: { unoptimized: true }`
- Tailwind CSS. No CSS-in-JS, no component library
- Content as typed TypeScript modules under content/. No CMS, no fetch calls
- Audio and images served from public/
- Record the exact versions installed in docs/build-notes.md.

## CONTENT MODEL

Shape it this way even though it is only local files today, because a real CMS replaces these modules later and the shape must survive that swap.

- artists: id, name, slug, bio, photo
- releases: id, title, slug, type (single, EP, album, compilation), releaseDate, artwork, trackIds array
- tracks: id, title, slug, artistId, durationSeconds, moodTags array, genreTags array, tempoBpm, coverArt, priceCents integer, currency, description, availableForLicensing boolean, ownershipNote, audio array of { variant, format, src } where variant is one of preview, master, instrumental, stem

A track references an artist by id, never by a name string. Prices are integer cents, never floats. Audio is an array of variants, never fixed fields.

## PAGES

- `/` homepage: hero, a short who-he-is line, featured tracks, a clear split into the fan path and the licensing path, email capture block
- `/music`: catalogue grid with artwork and inline preview playback
- `/music/[slug]`: track detail, preview player, price displayed, a disabled buy button reading that purchasing is coming soon, licensing note
- `/licensing`: ownership statement, catalogue filtered client-side by mood, genre and tempo, enquiry section that is a mailto link rather than a form post
- `/about`: biography and studio process
- Persistent audio player docked to the bottom of the root layout so playback survives navigation

Every route is statically generated. Track pages use generateStaticParams over the local content. No page performs a network request at runtime.

The email capture block and any form are visual only in this prototype. Make that obvious in the UI rather than silently doing nothing on submit.

## LEAD DECISIONS (follow these; they resolve ambiguities in advance)

1. **Scaffold manually, not with create-next-app.** create-next-app refuses this directory (capital letters in the folder name, and existing Client_Files/ and .claude/). design-dev writes package.json by hand (name `blueguitar-prototype`, private) and installs: `next`, `react`, `react-dom`, and dev deps `typescript`, `@types/node`, `@types/react`, `@types/react-dom`, `tailwindcss`, `@tailwindcss/postcss`, `postcss`. ESLint is optional (`eslint` + `eslint-config-next` are acceptable as part of a standard Next scaffold). Nothing else.
2. **Tailwind v4 is current stable and is CSS-first.** Design tokens live in an `@theme` block in app/globals.css; PostCSS uses `@tailwindcss/postcss`. A tailwind.config.ts is not required in v4; do not create one unless genuinely needed, and say so in components/README.md. If the installed major version is not 4, stop and message the main session.
3. **next.config.ts**: `output: 'export'`, `images: { unoptimized: true }`, `trailingSlash: true` (so every route exports as `folder/index.html` and works on any plain static server and on Cloudflare Pages). No basePath.
4. **tsconfig**: strict true, path alias `@/*` to the project root, and `exclude` must include `Client_Files`, `out`, `node_modules`.
5. **Colour sampling tool**: `sharp` is installed automatically as an optional dependency of `next`. design-dev may use it from a throwaway Node script (kept under components/ or styles/ as working notes, e.g. `styles/palette-extract.mjs`) to sample colours. That is not a new dependency. If `require('sharp')` fails after install, stop and message the main session. page-dev may use the same already-installed sharp ONLY to downscale the oversized images (over ~1 MB) to sensible web dimensions when copying into public/; record any resized file in build-notes. Do not otherwise alter artwork.
6. **Three artists**, as stated above (an earlier draft of the task said two in one place; three is correct).
7. **Shared type and site-config contract**, so design-dev and page-dev can work in parallel:
   - page-dev owns `content/types.ts` and creates it FIRST, exactly as below. design-dev's components may `import type` from `@/content/types` but import no content values. The only exception is `app/layout.tsx`, which imports `site` from `@/content/site` to feed the header, footer and email capture props.

   ```ts
   // content/types.ts
   export type AudioVariant = 'preview' | 'master' | 'instrumental' | 'stem';
   export type AudioFormat = 'mp3' | 'wav' | 'flac' | 'aac' | 'ogg';
   export interface AudioFile { variant: AudioVariant; format: AudioFormat; src: string; }
   export type ReleaseType = 'single' | 'EP' | 'album' | 'compilation';
   export type CurrencyCode = 'USD';

   export interface Artist { id: string; name: string; slug: string; bio: string; photo: string; }
   export interface Release {
     id: string; title: string; slug: string; type: ReleaseType;
     releaseDate: string | null; // ISO date; null = not yet confirmed (never invent one)
     artwork: string; trackIds: string[];
   }
   export interface Track {
     id: string; title: string; slug: string; artistId: string; durationSeconds: number;
     moodTags: string[]; genreTags: string[]; tempoBpm: number; coverArt: string;
     priceCents: number; currency: CurrencyCode; description: string;
     availableForLicensing: boolean; ownershipNote: string; audio: AudioFile[];
   }

   export type StreamingPlatform = 'spotify' | 'apple-music' | 'youtube' | 'amazon-music' | 'bandcamp' | 'soundcloud';
   export interface NavLink { label: string; href: string; }
   export interface StreamingLink { platform: StreamingPlatform; label: string; href: string; }
   export interface SiteConfig {
     name: string; tagline: string; label: string; location: string;
     nav: NavLink[]; streamingLinks: StreamingLink[];
     licensingEmail: string; footerNote: string;
     emailCapture: { heading: string; body: string; prototypeNotice: string };
   }
   ```

   - page-dev then creates `content/site.ts` exporting `export const site: SiteConfig`. Streaming URLs are unknown: use `#` hrefs and list them as placeholders. The licensing email is unknown: use `licensing@blueguitar.art` and list it as a placeholder awaiting the client's real address.
   - The release date of the album is unknown: `releaseDate: null`, and the album title is unknown, so use an obviously placeholder title such as "Untitled Album (placeholder)" and list it in build-notes.
8. **Player contract**: design-dev defines and documents (in components/README.md) a `PlayerProvider` + `usePlayer()` hook. Pages hand the player a small serialisable object (track id, title, artist name, cover art, preview src, page href) and components resolve nothing from content themselves. page-dev resolves `artistId` to an artist and picks the `preview` variant from the `audio` array in a helper under content/ (e.g. `content/index.ts` with `getArtist`, `getTrackBySlug`, `getPreviewSrc`, `formatPrice`, `formatDuration`).
9. **Client navigation**: all internal links use `next/link` so the root layout (and the audio element inside it) never unmounts. A plain `<a>` to an internal route would kill playback; qa-agent checks for this.
10. **Images**: every `<img>`/`next/image` has meaningful alt text passed in as a prop; decorative images use `alt=""` deliberately and sparingly.
11. **Ownership copy**: track 10's `ownershipNote` says it is a collaboration and that rights details are confirmed on enquiry, with no sole-ownership wording. Tracks 1 to 9 may say Robert Dempster is the writer, producer and rights holder of this recording, with details confirmed on enquiry. No blanket catalogue-wide claims anywhere.
12. The final dev server is started by the main session at the end. Teammates may run `npm run dev` or `npx serve out` briefly to verify, but must stop what they start and should use non-default ports if 3000 is busy.
